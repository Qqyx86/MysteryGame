# 问题与修复记录

## 问题一：替代证据被误写成“全部满足”

**现象**

在完整的门禁路线中，玩家已经取得“钟楼铜屑上的门禁残码”，但机械室“按编号检查齿轮”仍被锁定，并错误提示缺少“窗外攀爬留下的纤维”。

**定位过程**

最初 `ChoiceDef.requiredClues` 只表达“全部线索必须存在”。机械分析原本有两种有效进入路线：

- 门禁残码路线：铜屑残码。
- 攀爬路线：雨衣纤维。

但实现把两个候选都当作必需条件，导致任一单一路线都无法满足，从而形成永远不可达的节点。

**修复**

在 `GameModels.ets` 中增加 `requiredAnyClues`，在 `GameEngine.ets` 的 `isChoiceAvailable()` 中按“至少满足一个”求值。机械分析和维护门开启改用替代证据，线路对比等确实需要多个证据的选择继续使用 `requiredClues`。

**回归**

新增测试 `alternative_route_evidence_unlocks_gear_analysis`。该测试使用门禁残码路线推进到机械室，并断言“按编号检查齿轮”可用。修复后 13 条测试全部通过，模拟器中的完整 A+ 路径可正常到达真相结局。

## 问题二：自动存档只写缓存未落盘

**现象**

早期实现只调用 `Preferences.put()`。选择和内存状态会变化，但关闭进程后重新打开时存在无法可靠恢复的风险。

**定位与依据**

华为官方 Preferences 文档说明，异步写入需要继续调用 `flush()` 才会持久化到文件；本机 SDK 中 `put()` 与 `flush()` 也声明了异步异常。

**修复**

`GameRepository.save()` 现在在 `put()` 之后执行 `flush()`，并用 `try/catch` 记录具体错误后向 UI 抛出，使界面能够显示“存档失败”而不是静默丢失。随后执行了完整的进程结束与重启验证。

## 问题三：顶部系统状态信息破坏深色界面

**现象**

浅色状态栏在两段式截图和录屏中形成明显亮边，并显示模拟器系统任务标签，削弱沉浸感。

**修复**

在 `EntryAbility.onWindowStageCreate()` 中通过主窗口获得 `setWindowSystemBarEnable([])`，隐藏状态栏和导航栏；界面为顶部标题和底部主导航补充内边距。最终截图不再出现浅色系统栏。
